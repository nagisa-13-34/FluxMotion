## 🔴 高優先度 — 基本機能の完成

### 1. プロパティパネルの全プロパティ対応
**現状**: トランスフォーム（位置/スケール/回転/不透明度/アンカー）のみ
**目標**: レイヤータイプ別の全プロパティを編集可能に

| レイヤータイプ | 追加が必要なプロパティ |
|-------------|-------------------|
| テキスト | フォント、フォントサイズ、太さ、色、テキスト内容、行間、揃え |
| ソリッド | 色 |
| シェイプ | 塗り色、線色、線幅、角丸、シェイプ種類 |
| 全共通 | ブレンドモード、親子関係 |

**対象ファイル**: `Properties.tsx`, `Timeline.tsx`（展開プロパティ）

## 🔮 将来構想

### 14. Script / Plugin システム
ユーザーやサードパーティがFluxMotionの機能を拡張できるプラグイン基盤。
AEのエクスプレッションやスクリプトのように、自動化やカスタムエフェクトを実現する。

- [ ] プラグインAPI設計（レイヤー操作/レンダリング/UI拡張のインターフェース定義）
- [ ] JavaScriptベースのスクリプトエンジン統合
- [ ] エクスプレッション対応（プロパティ値をスクリプトで動的に計算）
- [ ] プラグインのインストール/管理UI
- [ ] プラグインマーケットプレイス（将来）

技術的な選択肢:
- Tauri側でV8/Denoを埋め込んでサンドボックス実行する方式
- WebWorkerでプラグインを隔離実行する方式
- WASMプラグイン（Rust/C++で書かれた高速プラグイン対応）

ライセンスの観点から、プラグインエコシステムを育てるにはMITライセンスが最適。
GPLだとプラグインのライセンスにも制約がかかるので商用プラグインが作りにくくなる。

---

### 15. 3DCG統合
Blenderのような3Dモデリング/アニメーション/レンダリング機能をアプリ内で実現する。

#### Phase 1: 3Dビューポート
- [ ] Three.jsまたはBabylon.jsの統合
- [ ] 3Dカメラ/ライトレイヤーの追加
- [ ] 2Dレイヤーと3Dレイヤーの共存（AEの3Dレイヤー方式）
- [ ] glTF / OBJ / FBXモデルのインポート

#### Phase 2: 3Dモデリング
- [ ] 基本プリミティブ（Cube / Sphere / Cylinder / Plane）
- [ ] メッシュ編集（頂点/辺/面の選択と移動）
- [ ] マテリアル/テクスチャの設定
- [ ] UV編集

#### Phase 3: 3Dアニメーション/レンダリング
- [ ] ボーン/アーマチュアによるスケルタルアニメーション
- [ ] PBRレンダリング
- [ ] シャドウ/ライティング
- [ ] パーティクルシステム

技術スタックの候補:
- フロントエンド: Three.js（MIT）で3Dシーンを構築
- バックエンド: wgpu（Rust）でネイティブGPUレンダリング
- 物理演算: rapier（Rust / Apache-2.0）
- WebGPUの既存実装（webgpuRenderer.ts）を拡張してシェーダーを追加

## 現在の技術的負債

| 項目 | 詳細 |
|------|------|
| プロパティ展開 | トランスフォーム5種のみ。色・テキスト・シェイプの展開が未対応 |
| アニメーション値の反映 | `getAnimatedValue` は実装済みだがレンダラーとの統合が一部不完全 |
| KF複数ドラッグ | 基本実装済みだが、大量KFの同時移動でパフォーマンス低下の可能性 |
| 型安全性 | プロパティキーが `string` ベースで型チェックが弱い箇所あり |
| テスト | ユニットテスト・E2Eテスト未作成 |
